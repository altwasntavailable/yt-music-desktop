# Contributing

Thanks for helping improve YT Music Desktop.

## Development setup

Requirements:

- Windows 10/11
- Node.js 20 or newer
- npm

```bash
npm install
npm test        # run the Node unit tests
npm start       # run the app
npm run dev     # run with development logging
```

Build outputs:

```bash
npm run dist            # NSIS installer
npm run dist:portable   # portable executable
npm run pack            # unpacked app in dist/win-unpacked
```

## Architecture

- `src/main/` — Electron main process: windows, tray, IPC, sessions, recovery,
  watchdog, downloads, the `ytmd-media` protocol, updater, and third-party
  lookups.
- `src/preload/` — the narrow, context-isolated IPC bridge exposed to the desktop
  renderer.
- `src/renderer/` — the desktop chrome, drawer UI, and offline library/player. It
  also probes the embedded YouTube Music player for track/queue state.
- `src/main/download-utils.js` — pure format, filename, and yt-dlp argument
  helpers for M4A/MP3/MP4. Keep this module free of Electron imports so it stays
  unit-testable.
- `src/main/downloads.js` — yt-dlp/FFmpeg detection, verified tool downloads and
  updates, folder/index handling, download jobs, and the offline library.
- `src/main/desktop-integration.js` — taskbar thumbnail buttons, jump list,
  taskbar progress/overlays, notifications, sleep timer, and launch-at-login.
- `test/` — Node unit tests for the pure download and desktop-integration
  helpers. Run them with `npm test`.

Keep renderer access narrow: add IPC handlers in `main.js`, expose only the
needed method in `chrome-preload.js`, and validate/sanitize all input in the
main process. IPC handlers must keep the sender check that restricts calls to
the app's own renderer.

Icon assets, including `assets/thumbar/` and `assets/overlays/`, are generated by
`scripts/generate-icons.js`; do not hand-edit the generated PNGs.

## Pull requests

- Keep changes focused and explain the user-facing effect.
- Run `npm test`, `node --check` on changed JavaScript files, and `npm run dist`
  when changing packaging or main-process code.
- Include screenshots for UI changes. Generate screenshots and the demo from a
  temporary profile with no account data, and keep the demo muted.
- Never commit `node_modules`, `dist`, signing material, cookies, logs, or user
  data. The existing `.gitignore` covers the usual cases.
- For download changes, test with:
  - a single track as M4A, MP3 (fixed bitrate and best VBR), and MP4 (480p,
    720p, 1080p, and best)
  - FFmpeg available and unavailable; confirm M4A and progressive MP4 still work
    without it
  - tags/cover art and SponsorBlock cutting enabled, with an empty and a
    non-empty SponsorBlock category list
  - a playlist download with at least two tracks, and confirm each track appears
    in the library as it finishes
  - changing the download folder in Settings and in the Offline panel, then
    playing an older download from the previous folder
  - installing and updating the app-managed yt-dlp, and confirming an external
    yt-dlp copy reports that in-app updates are unavailable
  - a duplicate download and a cancelled/failed download
- For desktop-integration changes, test the taskbar thumbnail buttons, jump
  list, progress/overlay, notifications while hidden, sleep timer, and Start
  with Windows in an installed build. These are Windows-only features.
